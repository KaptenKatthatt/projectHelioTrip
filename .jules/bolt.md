## 2024-05-18 - [Distance Calculation Micro-optimizations]
**Learning:** In Three.js, `distanceTo()` is implemented natively as `Math.sqrt(this.distanceToSquared())`. Replacing `distanceTo()` with `Math.sqrt(distanceToSquared())` provides zero performance benefit and only clutters the code.
**Action:** Only use squared distances (like `distanceToSquared()`) when the math allows us to *completely avoid* calculating the square root (e.g., fast rejection threshold checks). If the actual linear distance is required, simply use `distanceTo()`.
## 2024-06-25 - [Fast-rejection Distance Bounds]\n**Learning:** When evaluating N-body loop distance checks (like collision detection), you can pre-calculate the maximum dynamic movement (e.g., `moveDist`) before the loop. By adding this bound to the required threshold and using squared distances, you can skip costly per-body math for objects far away without using Math.sqrt().\n**Action:** Use squared distance early rejection checks (`distSq >= rejectLimit * rejectLimit`) before performing precise per-element math/distance resolution inside tight Three.js loops.
